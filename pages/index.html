clickdoc · open source · MIT

A doc you can click on.

clickdoc turns any folder of HTML pages into a documentation site where every block is annotatable in-place. Annotations live in a local SQLite file and surface through a plain-text feed any AI assistant can read.
stdlib only no dependencies SQLite WAL ~600 LOC

1Why

You write docs. People read them on their phone. They want to leave a remark without context-switching to a chat app, a Notion comment thread, or a GitHub issue. clickdoc lets them click on the line that bothers them and type their thought right there. The comment is stored locally and surfaced to any tool that wants to act on it — a human triager, a CI bot, or an AI coding agent running on the same machine.

It is intentionally small: one Python file, one SQLite database, three JS files, one CSS file. No build step. No npm. No Docker required.

2What it does

Anchor any element

Add data-anchor="some-id" to any HTML element. Click it → annotation panel opens, pre-loaded with the line excerpt. The annotation is bound to the anchor id so it survives page edits as long as the anchor stays.

Three annotation types

comment · a free thought. spec · turn this into a tracked spec/issue. precision · please clarify the doc. The type is structured so tools can route by intent — e.g. only spec annotations flow into a tracker.

Plain-text feed for AI agents

GET /api/feed returns one block per open annotation. Any local AI agent (Claude Code, Codex, Cursor, Hermes profile) can curl the feed at session start, read the queue, address items, and PATCH them as resolved.

Overlay pages for any project

The server ships a default pages/ folder. Point CLICKDOC_PAGES_DIR at your own folder and your pages override the defaults. Use it to keep framework public and content private. Same for CLICKDOC_STATIC_DIR.

Mobile-first

The TOC collapses, the floating + button is finger-sized, the modal panel hits the viewport edges on small screens. Made to be read from a phone while pacing.

Deploy as a systemd service or behind a Gateway

Ships with a systemd unit example, a Caddyfile, a Kubernetes Gateway API HTTPRoute, and a Docker Compose file. Pick your poison in api.html.

3Quickstart

$ git clone https://github.com/Juwebien/clickdoc
$ cd clickdoc
$ python3 server.py
[clickdoc] listening on http://0.0.0.0:8088
[clickdoc] db:           /home/<you>/.local/share/clickdoc/annotations.db

Open http://localhost:8088. Click the title. Type something. Submit. Open http://localhost:8088/api/feed and watch your comment appear in plain text.

Want your own pages instead of this welcome screen?

CLICKDOC_PAGES_DIR=$HOME/my-docs/pages python3 server.py

Run as a service? See ops/clickdoc.service, copy to ~/.config/systemd/user/, then:

$ systemctl --user daemon-reload
$ systemctl --user enable --now clickdoc.service

4Annotation anatomy

When you click a [data-anchor], the client captures:

{
  "page": "/pages/index.html",          // the URL path
  "anchor": "feat-types",                // data-anchor attribute (optional)
  "line_excerpt": "Three annotation...", // the clicked element's text
  "type": "comment|spec|precision",      // the intent
  "comment": "your message"               // what you typed
}

The server stores it with timestamps, an author tag (default anon, override via CLICKDOC_AUTHOR env or the panel), and a status. AI agents PATCH the status to addressed with a response field when they act on it.

5Security model — read this

clickdoc has no authentication. Treat the API as trusted-LAN-only. Put a reverse proxy with auth in front if you expose it beyond your machine. The default systemd unit binds 0.0.0.0:8088 — comment out that line and switch to 127.0.0.1 if you only want local access.

Annotations are stored as plain text in SQLite. Do not paste secrets (tokens, keys, passwords) into the comment field — they will sit on disk unencrypted. The annotation feed at /api/feed is also unauthenticated.

Page content is served as-is. If you mount an overlay dir via CLICKDOC_PAGES_DIR, anyone who can reach :8088 can read those pages. If your pages contain sensitive content, gate the server behind your normal auth.
